# Step 3：在理想时钟下实现 PN 捕获

Step 2 假设收发 PN 起点完全一致。Step 3 去掉这一条件：接收机已知 PN 规则和码片率，但不知道当前 PN 位置，需要自行搜索。

---

## 1. 问题边界

本步链路为：

```text
数据 -> PN 扩频 -> 未知整数 chip 延迟
     -> PN 捕获 -> 本地 PN 对齐 -> 解扩
```

捕获器输出：

| 输出 | 含义 |
| --- | --- |
| `LOCK` | PN 是否已可靠捕获 |
| `delayChips` | 估计的整数 chip 偏移 |
| `alignedPN` | 与接收信号对齐的本地 PN |

“理想时钟”只表示收发码片速率相同，不表示 PN 起点已知。本项目码片率为：

```text
Rc = 1.2288 Mchip/s
Tc = 1/Rc = 0.813802 us
```

Step 3 暂不处理：

- 分数 chip 延迟；
- 收发时钟频差；
- 载波频偏；
- 多径中的多个相关峰；
- Walsh 信道和帧同步。

---

## 2. PN 相位与滑动相关

PN 相位指 PN 序列中的位置，不是 QPSK 星座相位。设参考 PN 为 `p[n]`，接收信号为 `r[n]`，对每个候选偏移 `tau` 计算：

```text
C[tau] = sum(r[n+tau] * conj(p[n])), n=0...Ncoh-1
M[tau] = |C[tau]|^2
tauHat = argmax(M[tau])
```

偏移正确时，各 chip 同向累加，形成明显相关峰；偏移错误时，正负项大多互相抵消。复 PN 相关必须使用共轭。

初版可使用已知训练符号或连续导频，避免未知数据翻转破坏相干累加。若需要跨多个相位不连续的短块积累能量，应先求各块幅度平方，再非相干累加：

```text
M[tau] = sum_m |C_m[tau]|^2
```

教学 PN 周期为 31 chip，便于理解。最终 IS-95 短码周期为 32768 chip：

```text
32768 / 1.2288e6 = 26.6667 ms
```

32768 是短码周期，不是每个信息 bit 的扩频倍数。PN-I、PN-Q 的多项式、初态、移位方向和补零规则必须按课程规范冻结。

---

## 3. 不能只取最大值

噪声中也一定存在最大值，因此 `argmax` 只能产生候选相位，不能直接输出 `LOCK`。可使用峰值与背景之比：

```text
peakToFloor = max(M) / median(M)
```

超过门限后进入确认状态，并要求后续若干块的峰值持续超过门限且位置保持在允许窗口内：

```text
IDLE -> SEARCH -> VERIFY -> LOCK
          ^          |
          +--失败---+
```

门限需要在检测概率 `Pd` 和虚警概率 `Pfa` 之间折中：

```text
Pd  = 有信号时正确 LOCK 的比例
Pfa = 只有噪声时错误 LOCK 的比例
```

提高门限通常降低虚警，但会增加弱信号漏检。连续确认可以进一步抑制偶然噪声峰。

---

## 4. 捕获结果如何用于解扩

捕获器得到 `delayChips` 后，应在统一时钟边界将对应相位装载到本地 PN NCO/LFSR。之后 PN 发生器每个 chip 正常前进，不需要反复移动整段数组。

必须区分：

| 名称 | 来源 |
| --- | --- |
| 传播延迟 | 无线传播路径 |
| 相关峰索引 | 相关结果中的数组位置 |
| 实现延迟 | 缓存、积分窗和流水线 |

本地 PN 零相位应扣除相关器固定延迟和已知配置延迟：

```text
pnPhase = peakIndex - correlatorLatency - configuredDelay
```

固定延迟应由设计计算和固定向量标定，不能通过手工删除样点凑出正确 BER。

## 5. PN 捕获在实际接收机中的位置

PN 捕获只是完整接收机 Searcher 的一个阶段：

```text
射频前端/ADC
-> AGC、直流偏置和粗频偏校正
-> Searcher 搜索导频 PN 相位
-> 候选峰确认
-> 初始化本地 PN
-> PN 和导频相位跟踪
-> Rake 解扩与合并
-> Walsh 信道分离
-> 帧同步、FEC 译码和 CRC
```

捕获和跟踪的职责不同：

```text
捕获：大范围搜索，启动或失锁时执行
跟踪：只检查当前相位附近，锁定后持续执行
```

两径 Rake 系统中，Searcher 可与 Finger 并行工作：

```text
                 +-> Finger 0：解调主径
ADC 公共缓存 ----+-> Finger 1：解调第二径
                 +-> Searcher：后台搜索新路径
```

搜索范围按状态调整：

| 场景 | 搜索范围 |
| --- | --- |
| 冷启动 | 完整 PN 周期 |
| 后台多径搜索 | 最大多径时延窗口 |
| 短时失锁 | 上次相位附近 |
| 局部搜索失败 | 扩大窗口，最后全周期重捕获 |

进入 `LOCK` 后，由 Early-Late 等跟踪环路维持对齐，无需持续遍历整个短码周期。

---

## 6. 全相位搜索如何加速

直接滑动相关适合作为正确性基准，但不应为 32768 个相位分别从头计算完整相关。可采用：

| 方法 | 特点 |
| --- | --- |
| 多路并行相关器 | 同时检查多个相位，以硬件资源换时间 |
| PN 匹配滤波器 | 流水输出连续相位的相关值，适合 FPGA |
| FFT 循环相关 | 一次得到整周期相关，适合软件或有 FFT IP 的系统 |
| 粗搜加精搜 | 短积分筛选候选峰，再用长积分确认 |
| 多级驻留 | 未过初级门限立即排除，通过后延长观察 |
| 窗口搜索 | 优先搜索上次相位或预计多径附近 |

直接相关和加速算法必须对同一输入给出一致的峰值位置。

实际系统还存在频偏和分数 chip 采样相位，搜索会由一维码相位扩展为码相位、采样相位和频率候选。残余频偏较大时，可用短相干积分加非相干累加，避免长积分中的相位旋转抵消相关峰。

## 7. 帧设计与 CRC 处理

以下串行示意只适用于单路突发链路：

```text
| 前导 | 同步信息 | 帧头 | 业务数据 | CRC |
```

本项目的导频、同步和业务由不同 Walsh 码区分并同时发送，应分别设计。

### 7.1 导频与同步帧

导频是连续已知波形，用于 PN 捕获、跟踪和相位估计，不占用业务帧信息 bit。

同步信道以 `80 ms` 为完整帧时，编码前预算为：

```text
1.2 kbps * 80 ms = 96 bit
```

若使用 CRC-16：

```text
无卷积码尾比特：80 bit 同步内容 + 16 bit CRC
使用 K=9 零尾终止：72 bit 同步内容 + 16 bit CRC + 8 bit 尾比特
```

同步帧应周期性重复。CRC 覆盖范围、多项式、比特顺序和卷积码终止方式必须冻结。

### 7.2 业务帧

业务帧为 `20 ms` 时，编码前总预算为：

| 业务速率 | 总预算 |
| ---: | ---: |
| 2.4 kbps | 48 bit |
| 4.8 kbps | 96 bit |
| 9.6 kbps | 192 bit |

一种项目级 9.6 kbps 帧设计为：

```text
8 bit   帧头
160 bit 业务净荷
16 bit  CRC
8 bit   K=9 零尾比特
--------------------
192 bit
```

帧头可包含帧类型、速率模式和序号。该布局是教学方案，不代表 IS-95 标准字段。

低速模式中 CRC 和尾比特占比较高。例如 2.4 kbps 的 20 ms 帧只有 48 bit，可改用多个物理帧共用一次 CRC，或使用 `80 ms` 业务超帧。

### 7.3 CRC 失败

接收顺序为：

```text
Walsh 解扩 -> 去重复/软合并 -> 解交织
-> Viterbi 译码 -> CRC -> 交付净荷
```

CRC 只能检错，不能纠错。CRC 失败时：

```text
丢弃当前帧
payload_valid = 0
FER = FER + 1
```

单向链路若没有跨帧纠删码，错误帧只能丢失。可靠传输需要 ACK 和超时重传，并在帧头加入序号以识别重复帧：

```text
CRC 通过且是新序号 -> 交付并返回 ACK
CRC 通过但序号重复 -> 不重复交付，只返回 ACK
CRC 失败             -> 丢弃；未收到 ACK 后由发送端重传
```

项目初期没有反向链路时，只实现丢帧和 FER 统计。需要研究 ARQ 时，可先采用理想反馈通道。

同步 CRC 失败时，不得更新系统参数，应保留上一次有效配置并等待下一同步帧。单个业务 CRC 失败不代表 PN 失锁；只有连续失败且导频相关峰或跟踪误差同时异常，才触发重捕获。

## 8. 三个并行通道如何协同

三条逻辑信道分别进行 Walsh 扩频和功率分配，然后合路并统一进行 I/Q PN 扩频：

```text
导频符号 -> Wpilot   --乘 sqrt(Ppilot)--\
同步数据 -> Wsync    --乘 sqrt(Psync) ---+-> 合路 -> I/Q PN -> QPSK
业务数据 -> Wtraffic --乘 sqrt(Ptraffic)-/
```

发射端并行发送，接收机按顺序建立链路：

```text
导频 PN 捕获
-> PN 和载波相位跟踪稳定
-> 同步信道 CRC 通过
-> 获得帧边界和系统参数
-> 从下一个完整业务帧开始输出数据
```

业务有效条件可写为：

```text
business_valid = pn_lock
              && carrier_lock
              && sync_crc_ok
              && frame_boundary_valid
              && traffic_crc_ok
```

连续系统通常持续发送导频和周期同步信息，接收机自行接入，可能错过接入前的业务。点对点训练系统可分阶段启动：

```text
阶段 1：导频
阶段 2：导频 + 同步
阶段 3：导频 + 同步 + 业务
```

可先按 80 ms 超帧调试：第一个超帧捕获导频，第二个超帧确认同步，第三个超帧开始有效业务。最终保护时间应覆盖最坏捕获时间、跟踪稳定时间和至少一个同步帧。

没有反馈链路时，发射机不知道接收机是否已稳定，只能使用固定保护时间；有反向控制时，可等待接收机返回 `READY` 后再启动业务。

开启业务信道时必须保持既定功率预算，不能因重新归一化而意外降低导频功率。

---

## 9. 核心结论

1. 理想时钟表示码片速率一致，不表示 PN 起点已知。
2. 捕获通过全相位相关寻找候选峰，并用门限和连续确认输出 `LOCK`。
3. 冷启动进行大范围搜索，锁定后改由小范围跟踪；Searcher 可在后台搜索多径。
4. 直接相关是黄金模型，匹配滤波、并行相关和 FFT 可加速实际实现。
5. 捕获相位必须扣除相关器固定延迟，再装载到本地 PN 发生器。
6. CRC 失败帧不能交付；没有反馈或跨帧冗余时，该帧只能丢失。
7. 导频、同步和业务在发射端并行，接收机按“捕获、同步、业务”的顺序建立链路。
