# CDMA无线数据传输链路设计与实现零基础教学

本文面向通信零基础同学，目标是帮助你看懂题目、知道要设计什么系统、每个模块为什么存在，以及后续如何一步一步完成仿真、定点化和硬件验证。

题目要求设计的是一个参考 IS-95 体制的 CDMA 无线数据传输链路。你可以把它理解成：发送端把原始比特加工成适合无线传播的射频信号，信号经过噪声或衰落信道后，接收端尽量恢复出原始比特，并用误码率等指标证明系统性能满足要求。

---

原题关键信息如下：

| 项目 | 要求 |
| --- | --- |
| 系统类型 | CDMA 无线数据传输链路 |
| 工作频率 | 800 MHz |
| 扩频码片速率 | 1.2288 Mchip/s |
| 扩频码 | IS-95 短码 |

| 信道码 | IS-95 卷积码 |

一句话总结：你要搭建一个简化版 CDMA 基站到接收机的完整链路，包括发射机、无线信道、接收机、性能评估和硬件验证。

## 2. 先建立最基本的通信系统概念

通信系统的基本流程是：

```text
信息比特 -> 信道编码 -> 交织/成帧 -> 扩频 -> 调制 -> 无线信道 -> 解调 -> 解扩 -> 译码 -> 恢复比特
```

每个模块的意义如下：

| 模块 | 作用 | 类比 |
| --- | --- | --- |
| 信息比特 | 原始 0/1 数据 | 要发送的文字内容 |
| 信道编码 | 增加冗余，提高抗错能力 | 给句子加校验信息，方便纠错 |
| 交织 | 打散连续错误 | 把连续错误分散开，便于译码器处理 |
| 扩频 | 用高速码片扩展信号带宽 | 给每个用户分配独特节奏 |
| Walsh 码 | 区分逻辑信道 | 不同频道的标签 |
| 短 PN 码 | 形成 CDMA 扩频特征 | 伪随机扰码 |
| QPSK 调制 | 把比特映射成复数符号 | 把 0/1 变成可以发射的波形点 |
| 无线信道 | 添加噪声、衰落、多径 | 空气传播过程中的失真 |
| Rake 接收机 | 合并多径能量 | 把不同路径来的有用信号重新加起来 |
| 译码 | 利用冗余纠错 | 根据校验信息恢复原文 |

---

## 3. CDMA 是什么

CDMA 的全称是 Code Division Multiple Access，中文是码分多址。

它的核心思想是：多个信道可以同时使用同一频段，但用不同的码来区分。接收端知道目标码，就能把想要的信道解出来，并把其他信道尽量压下去。

本题中至少有三条逻辑信道：

| 逻辑信道 | 作用 |
| --- | --- |
| 导频信道 | 提供相位、幅度、信道估计参考，通常不承载用户数据 |
| 同步信道 | 帮助接收机获得系统时间、帧结构等同步信息 |
| 业务信道 | 真正承载用户数据，比如 2.4/4.8/9.6 kbps 数据 |

三条逻辑信道通过 64 位 Walsh 码区分。Walsh 码之间具有正交性，理想同步条件下互相干扰较小。

## 4. 扩频、码片和业务速率

题目给出扩频码片速率：

```text
Rc = 1.2288 Mchip/s
```

码片 chip 不是业务数据 bit。CDMA 会把一个低速业务比特变成很多高速码片，这就是扩频。

业务速率有三档：

```text
Rb = 2.4 kbps、4.8 kbps、9.6 kbps
```

扩频增益可以粗略理解为：

```text
扩频增益 = 码片速率 / 业务速率
```

以 9.6 kbps 为例：

```text
1.2288 Mcps / 9.6 kbps = 128
```

这说明每个业务比特大约对应 128 个码片。业务速率越低，扩频增益越高，抗干扰和抗噪声能力通常越强。

## 5. 本系统的推荐总体结构

建议把系统拆成下面几个部分。

```text
发送端
  随机比特生成
  IS-95 卷积编码
  符号重复或速率匹配
  交织
  Walsh 码扩频
  IS-95 短码扩频
  QPSK 调制

信道
  AWGN 信道
  瑞利多径信道

接收端
  QPSK 解调
  短码解扩
  Walsh 解扩
  信道估计
  Rake 接收与最大比合并
  解交织
  Viterbi 卷积译码
  误码率统计
```

对于零基础学习，不建议一开始就同时做所有模块。应该先做最小系统，再逐步加复杂度。

## 6. 推荐学习和实现路线

### 第 1 阶段：只做最简单数字链路

目标：理解误码率和调制解调。

```text
随机比特 -> QPSK 调制 -> AWGN -> QPSK 解调 -> 误码率统计
```

你需要学会：

| 知识点 | 最低掌握要求 |
| --- | --- |
| 比特 | 只由 0 和 1 组成的数据 |
| QPSK | 每 2 个比特映射成一个复数符号 |
| AWGN | 加性白高斯噪声 |
| Eb/N0 | 衡量每比特能量相对噪声强度的指标 |
| BER | 误码率，错误比特数 / 总比特数 |

这一阶段先不用考虑 CDMA、卷积码、Rake。

---

### 第 2 阶段：加入卷积码和 Viterbi 译码

目标：理解信道编码如何降低误码率。

```text
随机比特 -> 卷积编码 -> QPSK -> AWGN -> 解调 -> Viterbi 译码 -> BER
```

卷积码的意义是加入冗余。接收端即使收到一些错误比特，也可以通过 Viterbi 算法推断出最可能的原始序列。

题目要求 IS-95 卷积码。IS-95 常见前向链路卷积码参数是：

```text
约束长度 K = 9
码率 R = 1/2
生成多项式可参考 IS-95 标准
```

实际写报告时，应以老师给的参考规范或 IS-95 标准文本为准。

---

### 第 3 阶段：加入 Walsh 码和多逻辑信道

目标：实现导频、同步、业务三条逻辑信道的码分复用。

```text
导频信道 -> Walsh 码 1 ->
同步信道 -> Walsh 码 2 -> 相加 -> 短码扩频 -> QPSK -> 信道
业务信道 -> Walsh 码 3 ->
```

Walsh 码长度是 64，因此每个输入符号会扩展成 64 个 Walsh 码片。不同逻辑信道使用不同的 Walsh 码。

设计建议：

| 信道 | 建议处理方式 |
| --- | --- |
| 导频信道 | 使用固定全 0 或固定符号，便于信道估计 |
| 同步信道 | 使用已知低速比特序列，方便调试 |
| 业务信道 | 使用随机比特，作为 BER 统计对象 |

注意：导频信道通常用于接收机估计信道相位和幅度。零基础实现时，可以先假设接收端完全知道导频位置和 Walsh 码。

---

### 第 4 阶段：加入 IS-95 短码扩频

目标：让系统具备 CDMA 的伪随机扩频特征。

IS-95 短码通常由 PN 序列产生。PN 是 pseudo-noise 的缩写，意思是伪噪声序列。它看起来像随机序列，但实际由确定的移位寄存器生成，收发两端只要初始状态一致，就能生成完全相同的码。

你需要明确：

| 项目 | 要求 |
| --- | --- |
| PN 码类型 | IS-95 短码 |
| 码片速率 | 1.2288 Mchip/s |
| I/Q 支路 | 通常分别使用 PN-I 和 PN-Q |
| 接收端 | 用相同短码进行解扩 |

短码扩频的基本操作可以理解为乘法：

```text
扩频后码片 = 原始符号 x PN码片
```

若采用 0/1 表示，需要先映射成 +1/-1 再相乘。

---

### 第 5 阶段：瑞利信道和 2 径 Rake 接收机

目标：处理多径衰落。

无线传播中，信号可能通过多条路径到达接收机。例如一条直达路径，一条经过建筑物反射的路径。每条路径有不同延迟、幅度和相位，这就是多径。

题目要求瑞利信道下提供 2 径 Rake 接收机，并采用最大比合并。

可以把 2 径信道表示成：

```text
r(t) = h0 * s(t - tau0) + h1 * s(t - tau1) + n(t)
```

其中：

| 符号 | 含义 |
| --- | --- |
| s(t) | 发送信号 |
| r(t) | 接收信号 |
| h0、h1 | 两条路径的复数信道增益 |
| tau0、tau1 | 两条路径的延迟 |
| n(t) | 噪声 |

Rake 接收机的思想是：分别对不同延迟路径进行解扩和相干合并，把多径能量利用起来。

最大比合并的基本形式是：

```text
y = conj(h0) * y0 + conj(h1) * y1
```

其中 y0、y1 是两条路径分别解扩后的符号，conj(h) 是信道估计值的共轭。这样做可以让信道强的路径权重大，信道弱的路径权重小。

## 7. 发射机模块设计

下面给出一个比较完整的发射机设计思路。

### 7.1 随机业务比特

业务信道输入可以用随机 0/1 序列：

```text
b = [0, 1, 1, 0, 1, ...]
```

需要分别支持三种业务速率：2.4 kbps、4.8 kbps、9.6 kbps。

仿真时可以先固定做 9.6 kbps，跑通后再扩展到另外两档。

### 7.2 卷积编码

卷积编码器接收 1 个比特，输出多个编码比特。若码率为 1/2，则每输入 1 个比特输出 2 个编码比特。

卷积编码提高可靠性，但会增加传输数据量。因此后续要通过扩频、调制和速率匹配安排好码片数量。

### 7.3 交织

交织把连续编码比特重新排列。它不改变 0/1 的数量，只改变顺序。

目的：如果信道中出现连续错误，解交织后错误会分散，Viterbi 译码更容易纠正。

### 7.4 Walsh 扩频

每条逻辑信道选择一个长度 64 的 Walsh 码。

示意：

```text
业务符号:     +1
Walsh码:      [+1, -1, +1, +1, ... 共64个]
扩频后码片:   [+1, -1, +1, +1, ... 共64个]
```

如果业务符号是 -1，则扩频结果等于 Walsh 码整体取反。

### 7.5 逻辑信道叠加

导频、同步、业务三条信道分别 Walsh 扩频后相加：

```text
x = Ap * pilot_walsh + As * sync_walsh + At * traffic_walsh
```

其中 Ap、As、At 是功率权重。初学阶段可以先全部设为 1，再根据性能调整。

### 7.6 短码扩频

逻辑信道叠加后的码片再乘以短 PN 码。IS-95 中 I/Q 支路会使用对应的 PN 序列。

简化理解：

```text
x_spread = x * pn
```

### 7.7 QPSK 调制

QPSK 将两个比特或两个实值支路映射为一个复数符号。常见归一化形式为：

```text
00 -> ( 1 + j) / sqrt(2)
01 -> (-1 + j) / sqrt(2)
11 -> (-1 - j) / sqrt(2)
10 -> ( 1 - j) / sqrt(2)
```

实际系统中要注意映射表必须和解调器一致。

## 8. 信道模块设计

### 8.1 AWGN 信道

AWGN 是 Additive White Gaussian Noise，加性白高斯噪声。

模型很简单：

```text
r = s + n
```

其中 s 是发送信号，n 是高斯噪声。

AWGN 是第一个必须跑通的信道，因为它最简单，最容易和理论性能曲线对比。

### 8.2 瑞利信道

瑞利信道表示无线信号经历随机衰落，接收幅度会忽大忽小。

2 径瑞利信道可以仿真为：

```text
r[k] = h0 * s[k] + h1 * s[k - D] + n[k]
```

其中 D 是第二条路径相对第一条路径的延迟，单位通常是采样点或码片。

## 9. 接收机模块设计

接收机和发射机基本是反向流程。

### 9.1 QPSK 解调

把接收复数符号变成软信息或硬判决比特。

建议优先使用软判决，因为 Viterbi 软判决译码性能更好。

### 9.2 短码同步与解扩

接收端必须知道短码相位。如果短码相位不对，解扩结果会严重错误。

学习阶段可以先做理想同步：假设接收端已经知道短码起点。

后续再考虑搜索同步。

### 9.3 Walsh 解扩

对目标逻辑信道使用对应 Walsh 码相关：

```text
业务信道输出 = sum(接收码片 * 业务Walsh码)
```

如果 Walsh 码正交且同步准确，其他逻辑信道的相关结果接近 0。

### 9.4 导频辅助信道估计

导频信道发送已知符号，接收端可以比较“收到的导频”和“应该收到的导频”，估计信道：

```text
h_hat = received_pilot / known_pilot
```

在 AWGN 信道中，信道可以近似看成 1。在瑞利信道中，h_hat 是 Rake 合并的重要依据。

### 9.5 Rake 接收机

2 径 Rake 接收机包含两个 finger，每个 finger 对应一条路径：

```text
finger 0: 对延迟 tau0 的信号解扩，得到 y0
finger 1: 对延迟 tau1 的信号解扩，得到 y1
合并: y = conj(h0) * y0 + conj(h1) * y1
```

### 9.6 Viterbi 译码

Viterbi 译码器根据卷积码网格结构，寻找最可能的原始比特序列。

输入最好是软信息，输出是恢复后的业务比特。

## 10. 性能仿真应该怎么做

题目要求“面向 AWGN 条件下定点端到端性能较理论值损失小于 0.4 dB”。

这句话可以拆成三层：

| 层级 | 含义 |
| --- | --- |
| 理论值 | 理想算法或理论 BER 曲线 |
| 浮点仿真 | 用 double/float 实现完整链路 |
| 定点仿真 | 用有限字长模拟硬件实现 |

你需要比较这些曲线：

```text
BER vs Eb/N0
```

判断标准是：在相同 BER 目标下，定点曲线相比理论或浮点曲线的 Eb/N0 损失小于 0.4 dB。

例如，如果 BER = 1e-4 时：

```text
浮点系统需要 Eb/N0 = 5.0 dB
定点系统需要 Eb/N0 = 5.3 dB
损失 = 0.3 dB，满足要求
```

如果定点系统需要 5.6 dB，则损失 0.6 dB，不满足要求，需要调整量化位宽、缩放或算法。

## 11. 定点化是什么意思

计算机仿真里常用浮点数，比如：

```text
0.123456789
```

硬件 FPGA 更适合用定点数，比如用 12 bit、14 bit、16 bit 表示数值。

定点化要决定：

| 内容 | 例子 |
| --- | --- |
| 总位宽 | 12 bit、14 bit、16 bit |
| 整数位 | 表示动态范围 |
| 小数位 | 表示精度 |
| 舍入方式 | 截断、四舍五入、饱和 |
| 溢出处理 | 回绕、饱和 |

定点化的关键风险是量化误差和溢出。位宽太小会导致性能下降，位宽太大又浪费硬件资源。

建议流程：

```text
浮点仿真跑通 -> 统计每个模块信号范围 -> 设定位宽 -> 定点仿真 -> 对比 BER 曲线 -> 调整位宽
```

## 12. 硬件验证应该怎么做

题目要求实现验证：

```text
定点算法 + USRP -> 交叉验证，逐比特一致
```

这意味着你不能只写仿真，还需要证明硬件或硬件接口输出与定点模型一致。

推荐验证路线：

| 阶段 | 验证内容 |
| --- | --- |
| C 定点模型 | 与浮点模型 BER 对比 |
| RTL/Vivado 仿真 | 与 C 定点模型逐点对比 |
| USRP 环回 | 发射和接收真实采样数据 |
| 信号发生器测试 | 检查接收机对已知输入的响应 |

逐比特一致通常指：同一组输入数据经过 C 定点模型和硬件实现后，关键输出比特完全相同。如果不一致，需要逐模块定位：编码器、扩频、调制、解扩、译码哪个环节开始不同。

## 14. 推荐的最小可行版本

如果你现在完全不会，建议先做一个最小可行版本，避免一开始被完整系统压垮。

### 版本 A：基础通信链路

```text
随机比特 -> QPSK -> AWGN -> QPSK解调 -> BER
```

验收标准：BER 随 Eb/N0 增大而下降，并接近 QPSK 理论曲线。

### 版本 B：加入卷积码

```text
随机比特 -> 卷积编码 -> QPSK -> AWGN -> 解调 -> Viterbi -> BER
```

验收标准：编码系统 BER 明显优于未编码系统。

### 版本 C：加入 CDMA 扩频

```text
随机比特 -> 卷积编码 -> Walsh扩频 -> 短码扩频 -> QPSK -> AWGN -> 解扩 -> Viterbi -> BER
```

验收标准：无噪声时端到端误码为 0；有噪声时 BER 曲线合理。

### 版本 D：加入三条逻辑信道

```text
导频 + 同步 + 业务 -> Walsh区分 -> 叠加 -> 短码扩频 -> QPSK -> 接收机
```

验收标准：能分别解出业务信道，同步和导频不破坏业务 BER。

### 版本 E：加入瑞利信道和 Rake

```text
CDMA发射机 -> 2径瑞利信道 -> 2径Rake最大比合并 -> 译码 -> BER
```

验收标准：Rake 合并性能优于只接收单径。

## 16. 初学者最容易踩的坑

| 问题 | 表现 | 解决方式 |
| --- | --- | --- |
| 比特映射不一致 | 无噪声也有误码 | 检查 QPSK 映射和解映射是否一致 |
| PN 码相位不一致 | 解扩后像噪声 | 先做理想同步，再做搜索同步 |
| Walsh 码编号混乱 | 解错逻辑信道 | 固定码表并在报告中写清楚 |
| 能量归一化错误 | BER 曲线整体偏移 | 检查 QPSK、扩频、信道噪声功率定义 |
| Eb/N0 和 SNR 混淆 | 理论曲线对不上 | 明确每比特能量、每符号能量、码率和扩频关系 |
| 定点溢出 | 性能突然变差 | 统计每级信号最大值，使用饱和和合适位宽 |
| Rake 延迟不准 | 合并无增益 | 确认两径延迟单位是采样点还是码片 |
| 硬件与软件不一致 | 逐比特验证失败 | 从最前级开始逐模块比较中间数据 |

## 21. 最后给你的理解框架

你可以把这个题目分成三句话理解：

1. 用 IS-95/CDMA 的方法，把低速业务数据变成扩频后的 QPSK 无线信号。
2. 让信号通过 AWGN 或瑞利多径信道，然后在接收端恢复业务比特。
3. 用 BER 曲线、定点损失和硬件逐比特一致性证明系统可靠。

如果你现在完全不懂通信，最重要的第一步不是读完整本标准，而是先把“随机比特 -> QPSK -> AWGN -> 解调 -> BER”跑通。这个小系统跑通后，后面的卷积码、扩频、Rake 都是在它上面逐层增加功能。
