# CDMA 无线数据传输项目的实现路线

本文给出一条从需求冻结到硬件验证的基本实现路线。它解释模块之间的先后关系和验收证据，不替代 IS-95、cdma2000 或项目指定版本的具体参数表。项目范围以[训练课件 part1 第 7 页](../../material/research-training-part1/README.md#第-7-页)为准：800 MHz、1.2288 Mchip/s、2.4/4.8/9.6 kbit/s 业务速率、IS-95 短码与卷积码、QPSK、AWGN 和指定瑞利信道、两径 Rake 最大比合并，以及导频、同步、业务三条逻辑信道。

## 1. 先冻结接口和验收口径

先把链路当成一个有明确输入和输出的系统，而不是马上写某个调制函数。需要形成一页接口表，至少固定以下内容：

| 项目 | 需要冻结的内容 |
| --- | --- |
| 数据 | 比特排列、帧长度、业务速率和测试向量 |
| 码 | IS-95 短码、Walsh 码、卷积码的版本、寄存器约定和输出位序 |
| 速率 | 比特、编码符号、调制符号和码片之间的倍率关系 |
| 数值 | 浮点归一化、定点格式、舍入和饱和规则 |
| 信道 | AWGN 的信噪比定义、瑞利两径参数、路径时延和增益 |
| 指标 | BER 曲线、比较点、理论曲线和允许的 0.4 dB 定点损失 |

所有标准参数都应能回到项目材料或已经核实的规范来源。没有确认多项式、寄存器初值、码相位或位序时，先把它标成待决项，不要用常见实现猜测。

## 2. 建立最小的浮点发端

发端可以按下面的方向组织：

```text
业务比特
  -> 速率适配/帧组织
  -> IS-95 卷积编码
  -> 逻辑信道映射
  -> Walsh 区分
  -> PN 扩频
  -> QPSK 调制
  -> 信道输入
```

第一版只需要产生一条可重复的端到端测试波形。导频、同步和业务信道先使用固定、可说明的配置；每一级都输出中间参考数据，例如编码比特、I/Q 符号、Walsh 后序列和码片序列。这样接收端出现错误时，可以定位到第一个不一致的边界。

不要一开始加入所有工程功能。项目课件指定的是三条逻辑信道和单条训练链路，不能把教学课件中展示的完整 cdma2000 系统功能自动扩大成当前交付范围。[part2 的系统教学材料](../../material/research-training-part2/README.md)用于理解结构，具体交付仍以 part1 的项目页为准。

## 3. 先用理想同步完成浮点收端

浮点收端先假定已知码相位、载波相位和路径参数，验证最基本的解调链路：

```text
接收复基带
  -> QPSK 解调
  -> PN 解扩
  -> Walsh 相关/信道分离
  -> 卷积译码
  -> 帧检查与 BER 统计
```

在 AWGN 下先画出 BER 与信噪比曲线，并和选定的理论参考比较。此阶段的目的，是确认调制、扩频、解扩、译码和能量归一化是一致的；不要同时引入定时偏差、频偏和多径，否则错误来源无法区分。

推荐的最小测试顺序是：

1. 无噪声、无信道失真，确认端到端 BER 为零。
2. 只加入 AWGN，确认 BER 曲线随信噪比变化方向正确。
3. 分别关闭卷积码、PN 或 Walsh，确认测试确实能观察到对应模块的作用。
4. 改变 2.4、4.8、9.6 kbit/s，确认速率适配不会改变码片时序约定。

## 4. 加入同步和导频

理想同步通过后，再拆开实现同步。导频提供接收端的参考，搜索器通过相关峰寻找 PN 码相位，跟踪器在后续时间内维持对齐。应把“捕获成功”定义成可测量条件，例如相关峰超过阈值并在允许的相位误差内保持若干个观测窗口。

同步模块的输出不应只有一个布尔值，还应记录估计的码相位、路径时延、相关峰值和锁定状态。这样可以判断 BER 变差究竟来自同步失败，还是来自后端解调和译码。part2 中的 PN 码发生器、同步、Searcher 和 Finger 页面可作为结构参考，不能替代项目对参数的确定。

## 5. 加入两径瑞利信道和 Rake

两径模型把同一发射波形复制为两条具有不同复增益和时延的路径，再叠加噪声。接收端为每条可分辨路径分配一个 Finger：

```text
接收波形
  -> 路径搜索
  -> Finger 1：延迟补偿、解扩、信道估计
  -> Finger 2：延迟补偿、解扩、信道估计
  -> 最大比合并
  -> 解调与译码
```

最大比合并前要先完成时间对齐和相位补偿。若第 i 条路径的信道估计为 `h_i`，对应的解调结果为 `z_i`，实现可以按明确的复数权重约定形成合并结果，例如使用与 `h_i` 共轭相关的权重；最终公式必须和代码中的信道估计定义保持一致。不要把未经对齐的两路样本直接相加。

先在固定两径参数下验证，再改变路径时延、功率比和衰落随机种子。每个测试都保存信道参数、同步估计、合并前后的信号以及 BER，保证结果可以复现。

## 6. 从浮点迁移到定点

定点化应在浮点链路稳定后进行。顺序建议是：

1. 统计每个模块输入和输出的幅度范围、均值和峰值。
2. 为 I/Q、相关累加器、信道估计和译码度量选择整数位与小数位。
3. 明确截断、舍入、饱和和溢出的规则。
4. 用同一组输入向量逐模块比较浮点和定点结果。
5. 最后再比较整条链路的 BER 和所需信噪比。

定点测试需要区分两种问题：逐样本数值误差，以及误码率指标是否受到影响。课件要求 AWGN 条件下定点端到端性能相对理论值损失小于 0.4 dB；因此应在相同 BER 定义、相同编码配置和相同能量归一化下比较，而不是只比较某一段波形的均方误差。[part1 第 13 页](../../material/research-training-part1/README.md#第-13-页)

## 7. RTL 实现和逐比特验证

RTL 实现按稳定的定点模块边界展开。每个模块都应有：输入输出时序、复位行为、有效信号定义、延迟、位宽和一个来自软件模型的参考向量。先做发端，再做收端；先做单模块，再做模块集成。

验证至少包括三层：

- **模块级**：检查编码器、PN 发生器、相关器、QPSK 映射和累加器。
- **链路级**：将 RTL 输出与定点软件模型逐比特比较，定位首个不一致的时钟周期。
- **性能级**：在可控的 AWGN 或回放信道下测 BER，确认硬件实现仍达到软件模型的指标。

不要只比较最终 BER。两个实现即使偶然得到相近 BER，也可能在帧边界、符号延迟或异常输入上不一致。逐比特参考数据和时序对齐证据更适合定位硬件问题。

## 8. 验收产物

每个阶段结束时保留可以复核的产物：

| 阶段 | 主要产物 |
| --- | --- |
| 规范冻结 | 参数表、假设、来源和未决问题 |
| 浮点基线 | 发端/收端代码、测试向量、BER 曲线 |
| 同步与 Rake | 捕获结果、路径参数、合并前后数据和瑞利信道测试 |
| 定点化 | 位宽表、量化规则、浮点/定点差异报告 |
| RTL | 仿真工程、波形、逐比特比较报告和资源时序结果 |
| 硬件联试 | 配置记录、测试仪器设置、采集数据和最终性能报告 |

这条路线的核心是保持同一套参考数据贯穿浮点、定点、RTL 和硬件。每增加一个真实因素，就增加一组能单独验证该因素的测试，这样才能知道性能变化来自算法、信道、数值精度还是实现时序。
