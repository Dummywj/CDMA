# 基线业务载荷定义

## 决策

从基线 v2 开始，每个业务帧固定为 192 个业务位，帧长为 20 ms。帧内不添加 CRC，也不添加卷积编码尾零；卷积编码器每帧从零状态开始，Viterbi 使用截断模式，不假定最终状态为零。

四个业务帧组成一个 80 ms 批次，因此每批业务输入为 768 位，业务速率为 9600 bit/s。`FramePack` 与 `PayloadExtract` 在教学模型中保留为固定尺寸的透传接口，便于后续替换为实际帧组织逻辑。

## 覆盖的旧约定

本决策覆盖此前“172 位有效载荷 + 12 位 CRC + 8 个尾零，共 192 位”的教学方案。旧方案中的 CRC、FER 和尾比特统计不属于当前基线结果，当前扫描只输出 BER。

## 扫描约定

默认调用 `run_baseline(1000)`，每个 Eb/N0 点运行 1000 批，即 4000 个业务帧、768000 个业务位。扫描点为 `-4:0.25:6`，另执行独立无噪声检查，不计入扫描 CSV；输出为 `ber.csv`、`ber.png`、`diagnostic.mat` 和 `model.png`。零误码点标为未观测到错误，不用 `0.5/N` 估计，也不宣称真实 BER 为零。

当前范围是单径 AWGN、理想同步和三路信道叠加，并保留同步支路测试；不包含长码、功控和成形滤波。
