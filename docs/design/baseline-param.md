# 浮点基线仿真参数与序列定义

## 1. 适用范围与代码入口

本文记录当前 v2 浮点仿真的默认参数，以及业务、同步、导频三条信道实际发送什么序列。参数依据当前代码整理；文中的序列样例和功率数值已用 MATLAB 运行核对。

本版业务帧采用 **192 个业务位、无 CRC、无尾零**，遵循[基线载荷决策](../decisions/02-baseline-payload.md)。业务帧为 20 ms，同步信道帧为 26 2/3 ms，导频连续发送，遵循[帧长度决策](../decisions/01-frame-length.md)。80 ms 是代码一次处理的批次，包含 4 个业务帧和 3 个同步帧。

| 项目 | 当前默认值 |
| --- | --- |
| 仿真范围 | 单径复基带 AWGN、浮点运算、理想同步 |
| 码片速率 | 1,228,800 chip/s |
| 批次时长 | 80 ms |
| 每批码片数 | 98,304；每个码片对应一个复数采样 |
| 业务源速率 | 9,600 bit/s，每帧 192 位、每批 768 位 |
| 同步源速率 | 1,200 bit/s，每帧 32 位、每批 96 位固定测试数据 |
| 导频源 | 不承载业务数据，等效全零比特映射为全 +1 符号 |
| 业务 / 同步 / 导频 Walsh 码 | W1 / W32 / W0，长度均为 64 |
| 业务与同步卷积码 | K=9，R=1/2，八进制生成多项式 `[753 561]` |
| 业务 / 导频 / 同步幅度 | 1 / 0.5 / 0.25 |
| 业务 / 导频 / 同步功率比 | 16 : 4 : 1 |
| 短 PN 周期 | I、Q 各 32,768 chip，每批重复 3 个周期 |

代码入口：

- [`init_baseline.m`](../../matlab/baseline/init_baseline.m)：默认参数、Walsh 码、交织索引和卷积码网格。
- [`baseline_step.m`](../../matlab/baseline/baseline_step.m)：各阶段的序列生成和处理。
- [`short_pn.m`](../../matlab/baseline/short_pn.m)：I、Q 两路短 PN 序列。
- [`build_baseline.m`](../../matlab/baseline/build_baseline.m)：三路信道连接、叠加以及端口尺寸。
- [`run_baseline.m`](../../matlab/baseline/run_baseline.m)：噪声参数、随机种子和 BER 扫描。

`init_baseline` 会保留工作区中已有且结构有效的 `cfg`，因此本文默认值不一定等于用户修改后的工作区值。恢复默认值可执行 `clear cfg; init_baseline`；`run_baseline` 会自行重建默认配置。

## 2. 业务信道比特序列

### 2.1 生成方式

`TrafficSource` 接收批次时间 `t`，使用下面的代码生成业务数据：

```matlab
batch = round(real(u(1))/cfg.batchSeconds);
stream = RandStream('mt19937ar', 'Seed', cfg.seed + batch);
y = double(rand(stream, 768, 1) >= 0.5);
```

其中 `cfg.seed = 20260927`，`cfg.batchSeconds = 0.08`。

| 批次编号 | 调用时间 | 业务源种子 |
| --- | --- | --- |
| 0 | 0 s | 20260927 |
| 1 | 0.08 s | 20260928 |
| 2 | 0.16 s | 20260929 |

业务输入是可复现的伪随机 0/1 测试数据：均匀随机数小于 0.5 时取 0，否则取 1。生成规则给 0、1 相同的概率，但不要求某个有限帧内各有一半。代码每批重新创建随机流，同一个批次编号会得到相同的数据，不同批次使用不同种子。各个 Eb/N0 测试点使用相同的业务序列，以便比较。

默认第 0 批的前 64 位为：

```text
0011101111001000001001001000101010001011011111010101110001010010
```

### 2.2 帧划分与长度变化

`reshape(u,192,4)` 按列组织 4 帧：第 1～192 位属于第 1 帧，第 193～384 位属于第 2 帧，依次类推。`FramePack` 直接透传，不插入 CRC、尾零或其他开销。

```text
每帧：192 业务位 → 384 卷积编码位 → 384 交织位 → 24,576 Walsh 码片
每批：768 业务位 → 1,536 卷积编码位 → 1,536 交织位 → 98,304 Walsh 码片
```

业务交织逐帧执行，使用 `bro(384,6,6)`。交织后的每个比特先通过 `1-2*b` 映射为 +1 或 -1，再乘一整个 64 码片的 W1，最后乘业务幅度 1。

## 3. 同步信道比特序列

### 3.1 固定的 96 位测试模式

`SyncSource` 不根据时间生成新数据，每次都返回同一组 96 位：

```matlab
y = double(mod((0:95)' + floor((0:95)'/7), 2));
```

等价地，令 `k=0,1,...,95`：

```text
b_sync[k] = (k + floor(k/7)) mod 2
```

在这 96 位内部，基本模式是 `0101010`，重复 13 次后再取 `01010`，总计 `13×7+5=96` 位。每批重新从该模式的第 1 位开始；由于 96 不是 7 的整数倍，跨批次的整个序列不能简单理解为永不停顿的 7 位周期。

按每个同步帧 32 位划分，本批实际输入为：

| 同步帧 | 32 位输入 |
| --- | --- |
| 第 1 帧 | `01010100101010010101001010100101` |
| 第 2 帧 | `01001010100101010010101001010100` |
| 第 3 帧 | `10101001010100101010010101001010` |

这是一组用于验证物理层支路的固定测试数据，没有打包真实的同步消息、系统时间、系统标识等字段，也没有额外插入同步字。当前接收端依靠理想同步，未从这组数据获取帧边界或系统时间。

### 3.2 编码、重复和 Walsh 覆盖

```text
每帧：32 输入位 → 64 卷积编码位 → 重复后 128 位 → 128 交织符号
      → 每符号覆盖 4 个 W32 周期 → 32,768 码片

每批：96 输入位 → 192 卷积编码位 → 重复后 384 位 → 384 交织符号
      → 98,304 码片
```

具体处理为：

1. 对整批 96 位做卷积编码，状态处理见第 6 节。
2. `repelem(u,2)` 将每个编码位重复两次；这里是重复已有位，不是补零。
3. `reshape(...,128,3)` 后逐同步帧使用 `bro(128,7,1)` 交织。
4. 将比特映射为 ±1；`repelem(...,4)` 让每个交织符号覆盖 4 个 Walsh 周期。
5. 每个 Walsh 周期为 64 chip，因此每个交织符号覆盖 256 chip，再乘同步幅度 0.25。

对应的速率依次为 1.2 kbit/s、2.4 kbit/s、4.8 ksymbol/s，最终码片速率为 1.2288 Mchip/s。

## 4. 导频信道序列

导频分支由常量块 `PilotAmplitude` 输入 `cfg.pilotAmplitude=0.5`，`PilotWalsh` 直接生成：

```matlab
y = real(u(1)) * ones(cfg.chipsPerBatch, 1);
```

所以每批输出都是 98,304 个 `+0.5`。代码没有显式生成导频比特，也没有给导频做卷积编码或交织；其等价过程是：

```text
全零比特 → 0 映射为 +1 → 乘全 +1 的 W0 → 乘幅度 0.5
```

这只是 PN 扩频之前的序列。导频随其他信道共同乘上 `cfg.pn` 后，其单独的复基带分量为 `0.5*cfg.pn`，不再是恒定的实数。

## 5. Walsh 码定义

本模型使用 MATLAB `hadamard(64)` 生成的 Sylvester 行序，以 W0 为第 0 个码字。MATLAB 数组从 1 开始，所以 Wk 对应 `H(k+1,:)`。

```matlab
H = hadamard(64);
cfg.trafficWalsh = H(2,:).';
cfg.syncWalsh = H(33,:).';
```

| 信道 | 码字 | MATLAB 行号 | 完整的 64 码片模式 |
| --- | --- | --- | --- |
| 导频 | W0 | 第 1 行，代码直接生成全 +1 | `ones(64,1)` |
| 业务 | W1 | 第 2 行 | `repmat([1;-1],32,1)` |
| 同步 | W32 | 第 33 行 | `[ones(32,1);-ones(32,1)]` |

三个码字两两内积为 0，自身内积为 64。每路在其覆盖的完整 Walsh 周期内，先将数据符号与码字相乘，再做幅度加权；三路在 `ChannelSum` 中逐码片相加。业务使用 W1 是当前项目配置，不表示所有业务信道必须采用 W1。

## 6. 卷积编码与状态约定

### 6.1 公共编码参数

业务与同步使用同一个网格：

```matlab
cfg.trellis = poly2trellis(9, [753 561]);
```

| 参数 | 当前取值与含义 |
| --- | --- |
| 约束长度 K | 9：当前输入位和之前 8 位参与编码 |
| 记忆长度 | 8 位，共 256 个编码器状态 |
| 码率 R | 1/2：每输入 1 位，输出 2 位 |
| 类型 | 二进制前馈卷积码，无穿孔 |
| 生成多项式 | `[753 561]`，数字按八进制解释 |
| 输出顺序 | 每个输入位先输出 753 对应结果，再输出 561 对应结果 |

若寄存器按 `[当前输入位, 前1位, ..., 前8位]` 排列，抽头掩码如下，选中项作模 2 相加：

| 八进制表示 | 9 位二进制掩码 | 选中的输入延迟 |
| --- | --- | --- |
| 753 | `111101011` | 0、1、2、3、5、7、8 |
| 561 | `101110001` | 0、2、3、4、8 |

位序和掩码已由 [`verify_baseline.m`](../../matlab/baseline/verify_baseline.m) 中独立的移位寄存器实现与 `convenc` 对照。

### 6.2 业务与同步的状态不同

业务：每个 192 位业务帧独立调用 `convenc(data(:,k),cfg.trellis)`，从零状态开始。帧末不追加 8 个尾零，因此最终状态不一定是零。接收端使用 `vitdec(...,40,'trunc','unquant')`，输入为未量化的软值，输出为业务比特。

同步：整批固定 96 位模式循环发送，代码先计算发送一遍该模式后的状态，再用该状态作为实际输出的初始状态：

```matlab
[~, state] = convenc(u, cfg.trellis);
y = convenc(u, cfg.trellis, state);
```

默认模式对应 `state=82`。第一遍调用只求状态，其输出不发射；第二遍产生本批的 192 个编码位。对这组固定循环输入，这等价于编码器进入周期运行后连续发送该模式：不在 32 位同步帧边界复位，批次之间的编码状态也保持一致。代码并未保存任意输入情况下的跨批次状态；若以后改成逐批变化的真实同步消息，需要另行实现连续状态传递。

## 7. 幅度、功率分配与噪声口径

### 7.1 三路信道的相对功率

三个配置字段是幅度，平均功率按幅度的平方计算。以下是模型中的归一化相对量，不是瓦特或 dBm：

| 信道 | 配置字段 | 幅度 A | 功率 A² | 占三路总平均功率 |
| --- | --- | --- | --- | --- |
| 业务 | `trafficAmplitude` | 1 | 1 | 16/21，约 76.19% |
| 导频 | `pilotAmplitude` | 0.5 | 0.25 | 4/21，约 19.05% |
| 同步 | `syncAmplitude` | 0.25 | 0.0625 | 1/21，约 4.76% |

因此业务、导频、同步功率比为 **16:4:1**，三路总平均功率为 `1+0.25+0.0625=1.3125`。这是完整对齐的 Walsh 周期上利用正交性得到的平均结果；不能把某一个码片的叠加幅度平方直接当成整批平均功率。模型没有再把叠加后的总功率归一化为 1。

`cfg.pn` 的模长为 1，所以 `IQSpread` 不改变叠加信号的模平方。默认第 0 批实测三路平均功率分别为 `1、0.25、0.0625`，`ChannelSum` 与 `IQSpread` 输出的平均功率均为 `1.3125`。

这些幅度属于本次仿真实验的选择，不是标准强制的固定功率分配。

### 7.2 AWGN 参数

初始化的 `cfg.EbNoDb=4`，`cfg.noiseEnabled=true`。`run_baseline` 默认扫描 `-4:0.25:6` dB，并使用 2 dB 生成单批诊断数据。

这里 Eb 指业务信道每个 192 位载荷中的业务位能量，业务速率为 9,600 bit/s。复噪声样本的总方差为：

```text
variance = trafficAmplitude² × 1,228,800 / (9,600 × 10^(EbNoDb/10))
         = 128 / 10^(EbNoDb/10)    （默认业务幅度为 1）
```

实部与虚部各分配一半方差，代码为 `sqrt(variance/2)*(randn + 1j*randn)`。导频和同步功率没有计入业务 Eb；`EbNoDb` 也不是三路叠加信号每个复采样的总信噪比。

噪声使用独立创建的 `mt19937ar` 流，种子为 `cfg.seed+100000+batch`。业务数据和噪声分别可复现；同一批次在不同 Eb/N0 点使用相同的标准噪声样本，只改变其幅度。

## 8. I/Q 短 PN 序列

### 8.1 原始递推与周期扩展

`short_pn` 分别生成 I、Q 两条二进制序列。下表的“延迟”严格对应代码 `raw(n-lags)`，用于避免不同多项式记法造成位序歧义：

| 分支 | `lags` | 原始递推 |
| --- | --- | --- |
| I | `[15 10 8 7 6 2]` | `i[n] = i[n-15] ⊕ i[n-10] ⊕ i[n-8] ⊕ i[n-7] ⊕ i[n-6] ⊕ i[n-2]` |
| Q | `[15 12 11 10 9 5 4 3]` | `q[n] = q[n-15] ⊕ q[n-12] ⊕ q[n-11] ⊕ q[n-10] ⊕ q[n-9] ⊕ q[n-5] ⊕ q[n-4] ⊕ q[n-3]` |

`⊕` 表示模 2 相加。代码采用以下确定的初始化和起点：

1. I、Q 各自以 15 个全 1 位作为原始初值，从第 16 位开始递推，生成 32,767 位原始序列。
2. 分别寻找唯一的连续 14 个零，在其后插入一个零，将周期扩展到 32,768 位。
3. 循环移动序列，让“连续 15 个零之后的第一个 1”成为输出第 1 位；这是本模型的零偏移起点。

原始递推适用于插零之前的序列；插零和重新排列之后的序列才是本模型实际使用的 PN 位序列。每路输出均有 16,384 个 1、16,384 个 0，末尾 15 位为 0。

默认起点的前 32 位为：

```text
I: 10101001001110100011011110011001
Q: 10011110101110101101001110001010
```

### 8.2 复数表示与批次对齐

两路 PN 位分别映射为 ±1，再构成单位模复数：

```matlab
code = complex(1 - 2*iBits, 1 - 2*qBits) / sqrt(2);
cfg.pn = repmat(short_pn(), 3, 1);
```

一个周期的时长是 `32768/1228800 = 26 2/3 ms`，一个 80 ms 批次恰好覆盖 3 个周期，得到 98,304 项 `cfg.pn`。每批复用同一个向量时，PN 码相位恰好回到周期起点。

二进制 PN 本身不是复数；代码用实部、虚部分别保存 I、Q 两路映射结果。实际前 4 个复数 PN 值为：

```matlab
[-1-1j; 1+1j; -1+1j; 1-1j] / sqrt(2)
```

三路 Walsh 信号先逐码片相加，再共同使用这一个 I/Q PN 向量：

```text
u[k] = traffic[k] + sync[k] + pilot[k]
pn[k] = (cI[k] + j*cQ[k]) / sqrt(2)
y[k] = u[k] × pn[k]
```

这里 `cI[k]、cQ[k]` 均为 ±1。`IQSpread` 实现 `y=u.*cfg.pn`；理想同步接收端使用同一码相位，执行 `real(y.*conj(cfg.pn))`。当前没有基站间不同 PN 偏移配置，也没有实现额外的业务长码扰码。

## 9. 参数检查与复现

在项目根目录的 MATLAB 命令窗口执行以下代码，可以重建本文引用的默认序列并检查已有的编码、PN 和状态约定。`clear cfg` 会清除当前自定义配置：

```matlab
addpath('matlab/baseline');
clear cfg;
cfg = init_baseline();

trafficBits = baseline_step('TrafficSource', 0);
syncBits = baseline_step('SyncSource', 0);
pilotChips = baseline_step('PilotWalsh', cfg.pilotAmplitude);
[pnPeriod, iBits, qBits] = short_pn();

char(trafficBits(1:64).' + '0')
char(reshape(syncBits,32,3).' + '0')
cfg.trafficWalsh.'
cfg.syncWalsh.'
pilotChips(1:8).'
char(iBits(1:32).' + '0')
char(qBits(1:32).' + '0')
pnPeriod(1:4)

verify_baseline;
```

本参数表描述当前教学仿真实现。帧时序和短 PN 等配置沿用项目物理层约定，但 192 位全业务载荷、固定同步测试模式、业务 Walsh 分配和相对幅度包含明确的教学选择；不能据此将模型视为完整的 cdma2000 互通实现。模型范围和运行入口见[浮点链路基线](baseline.md)，已有测量结果见[基线仿真结果](baseline-results.md)。
