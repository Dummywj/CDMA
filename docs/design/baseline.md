# 浮点链路基线

## 1. 基线定位

本基线用于先验证 CDMA 业务信道的浮点收发链路，作为后续加入捕获、跟踪、多径、定点和硬件实现之前的参考实现。基线关注发送端和接收端算法接口是否一致，以及在 AWGN 条件下的误码率和误帧率表现。

当前基线不用于验证完整的实际接收机捕获流程。

## 2. 信道模型

信道采用单径复基带 AWGN 模型：

```text
y[n] = x[n] + w[n]
```

其中 `x[n]` 是发射复基带采样，`w[n]` 是复高斯白噪声。模型暂不包含：

- 多径时延和多普勒扩展；
- 瑞利或其他衰落；
- 未补偿的载波频偏和相位偏差；
- 未补偿的采样定时偏差；
- 额外的射频非理想因素。

## 3. 理想同步假设

接收端直接获得正确的同步参数，包括：

- 采样和 chip 定时；
- 业务帧边界；
- PN 码相位和 Walsh 码相位；
- 载波频率和相位；
- 单径信道的增益补偿参数。

因此，基线暂不实现 Searcher、同步信道捕获、同步消息解码和导频跟踪。理想同步只表示这些参数已知，不表示实际系统不需要这些功能。

## 4. 收发链路

基线首先验证业务信道。业务信道遵循项目的 20 ms 帧设计；同步信道的 26 2/3 ms 帧和导频信道的连续参考序列保留在系统设计中，但不在本基线中承担接收端捕获功能。

业务链路的基本处理顺序为：

```text
业务比特
  -> 帧组织和速率适配
  -> IS-95 卷积编码
  -> 信道复用/信道化
  -> PN 扩频
  -> QPSK 调制
  -> 单径 AWGN
  -> 理想同步
  -> 解扩
  -> QPSK 软判决
  -> 解交织和卷积译码
  -> 恢复业务比特
```

由于信道只有一条路径，接收端使用一个解扩支路即可，不使用两路 Finger，也不使用 Rake 合并。

## 5. 暂不包含的模块

- Searcher 的 PN 捕获和路径搜索；
- 同步信道的实际解调与系统时间建立；
- 导频辅助的定时、频偏和相位跟踪；
- 两路或多路 Finger；
- Rake 合并；
- 瑞利多径信道；
- 定点量化、RTL 和硬件接口。

## 6. 验证目标

基线至少应支持以下检查：

1. 无噪声条件下端到端恢复业务比特；
2. 给定信噪比下重复运行结果一致；
3. 扫描信噪比并统计 BER、FER；
4. 保存固定输入、噪声种子和关键中间结果，便于后续定点和 RTL 逐级对比。

后续加入 Searcher、同步跟踪或 Rake 时，应继续保留本基线，作为理想同步单径链路的对照。
